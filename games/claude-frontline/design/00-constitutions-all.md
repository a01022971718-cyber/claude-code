> 原文件：`art/01-typography-constitution.md`

# X-S 字体美术宪法 v1.3

> 适用于游戏内所有文字：品牌字标、标题、正文、数据、标签与动态文字。
> 本宪法的每一条都已落成可复用代码：`css/style.css`（字体类与令牌）和 `js/brand.js`（字标、标志、逐字上升）。
> 优先级：本宪法 > 单个页面的临时设计。需要例外时，先修订宪法，再改页面。

## 第 1 章 品牌寓意：X-S 是什么

| 元素 | 形 | 意 |
|---|---|---|
| **X** | 四芒星旋转 45°，正好是一个 X | **未知**（方程里的未知数 x）与**新星**（新生） |
| **S** | 从左下升到右上的 S 曲线 | **向上**：Sigmoid 学习曲线，也是火箭爬升的轨迹 |
| **-** | 一条短横线 | **地平线**：从未知到新生的分界，破晓从这里升起 |
| 色彩 | 紫夜 → 破晓橙金，加一束探索青 | 夜（未知）→ 日出（新生），青光是去探索的那束光 |

一句话：**在未知的紫夜里，一颗新星沿着 S 曲线向上，迎来破晓。**

## 第 2 章 从原「Claude 战线」字标继承的三条美感

旧字标里值得保留的，不是那个名字，而是它的构成方式。下面三条被定为字标的基因：

1. **双色分工**：拉丁品牌字着色，中文用米白。两部分永远不同时着色，也不同时使用白色。
2. **标志先行、粗重几何**：标志放在字前，高度约为字高的 1.15 倍；字重用 900（中文 800），轮廓干净有力，不加描边。
3. **像素与矢量并置**：标志和字是平滑的矢量，旁边的角色和动效是像素。这种「锐利的字 + 颗粒的画」的反差就是风格本身。

## 第 3 章 字标规范

```
[标志]  X-S  战线
  │      │    └─ 中文：米白 #ede6d6 · 字重 800 · 字距 +0.06em
  │      └────── 拉丁：破晓渐变（下 #ff7a45 → 中 #ffb14a → 上 #ffe08a）· 字重 900 · 字距 +0.02em
  └───────────── 标志：高度 1.15em · 与字的间距 0.32em · 节拍时放大 ≤ 12%
```

- **渐变方向必须自下而上**（0°），象征「向上」。禁止左右渐变。
- **投影**：`0 3px 0 rgba(10,6,30,.65)` 的像素硬投影 + 英雄主光色柔光（18px，强度 0.25 + 节拍 × 0.35）。
- **最小尺寸**：字标 ≥ 20px；小于 20px 只用标志，不用字。
- **安全区**：四周至少留出 0.5 倍字高的空白。

**禁止**
- 中文也使用渐变或彩色；
- 拉伸、倾斜、加描边或外发光框；
- 把标志放到字后面，或单独旋转标志；
- 在浅色背景上使用破晓渐变（对比不足）。浅色背景改用深紫 `#1e1636` 单色字标。

| 令牌 | px | 字重 | 行高 | 字距 | 用途 |
|---|---|---|---|---|---|

| `--fs-4xl` | 39 | 900 | 1.1 | +0.08em | 大厅英雄名（桌面） |
| `--fs-3xl` / `.t-h1` | 31 | 800 | 1.15 | +0.05em | 页面主标题、英雄档案名 |
| `--fs-2xl` | 25 | 800 | 1.2 | +0.04em | 模式入口大字 |
| `--fs-xl` / `.t-h2` | 20 | 800 | 1.25 | +0.04em | 页眉条标题、弹窗标题 |
| `--fs-lg` / `.t-h3` | 16 | 700 | 1.3 | 0 | 卡片标题、引语 |

## 第 6 章 中英混排

1. 中文与拉丁字母、数字之间留一个空格（或 0.25em）：「主脑 T2」「Lv 6」。
2. **英文标签**全部大写、等宽、字距 +0.14em，使用英雄点缀色：`MISSION 01`、`X-S ORIGINAL`。
3. **引语与口头禅**用「」，书名号着英雄点缀色（`.t-quote`）。
4. 中文标点不挤压；数字后的单位用全角空格以外的普通空格分开（「90 秒」）。

---

## 第 7 章 数字

- 所有数值使用等宽数字（`font-variant-numeric: tabular-nums`），保证跳动时不抖。
- 资源数字跟随资源色：晶片金 `#e9b949`、语料青 `#3fd0c9`、算力紫 `#9b7bff`。
- 时间统一 `m:ss`；超过 1 小时用「X 时 Y 分」。
- 大数字超过 1 万缩写为 `12.3k`；分数结算时完整显示并加千分位。

## 第 8 章 色彩与可读性（实测对比度，背景为深空黑 `#0b0a12`）

| 文字色 | 对比度 | 允许用途 |
|---|---|---|
| 米白 `#ede6d6` | 15.8 : 1 | 正文、标题（首选） |
| 暗灰 `--dim #9d96ad` | 6.9 : 1 | 次要说明、说明文字 |
| 弱灰 `--mute #6c6680` | 3.6 : 1 | **仅限** ≥ 14px 粗体或装饰性文字，不得用于正文 |
| 破晓金 `#ffb14a` | 10.9 : 1 | 强调、字标 |
| 主按钮文字 `#2a1206` 在 `#ffb14a` 上 | 9.8 : 1 | 主按钮 |
| 白字在紫夜 `#33207a` 上 | 12.9 : 1 | 页眉条标题 |

规则：正文 ≥ 4.5 : 1，大字（≥ 18px 或 14px 粗体）≥ 3 : 1。英雄主光色只用于标题、名字和强调，不用于大段正文。

## 第 9 章 文字动效：「向上」

- **逐字上升**（`.t-rise` / `CF.Brand.rise()`）：每个字从下方 6px 处淡入上升，时长 320ms，逐字间隔 40ms，缓动 `cubic-bezier(.2,.8,.2,1)`。用于英雄名、结算标题等「登场」时刻，同一屏只用一次。
- **节拍呼吸**：字标的标志、光晕随 `--beat`（0–1）变化，缩放上限 12%。**文字本身永不随节拍抖动**，保证可读。
- **飘字**（伤害、拾取、收取）：上升 40–46px，0.9–1.1 秒内淡出；暴击用黄 `#fff35c` 并放大 1.4 倍，再回弹。
- **减少动效**：系统开启「减少动态效果」或在设置中开启「减少动效」时，以上动画全部关闭，只保留静态样式。

## 第 10 章 英雄字色

- 英雄名用该英雄的**主光色**（见《游戏界面视觉宪法》第 2 章色板）。
- 英雄主光色背景上的文字一律用白色或米白，不用同色系。
- 口头禅前后的「」用英雄点缀色，正文仍为米白。

## 第 13 章 主标题 Key Logo（v1.1 增补，v1.2 按主创要求修订布局）

> 第 3 章的字标继续用于页眉、弹窗等小尺寸场合；大厅、启动页、宣传图使用本章的主标题。参考王者荣耀、QQ 飞车等成熟游戏标题的做法：**有厚度、有材质、有副标、有动势**，同时第 2、3 章的规则全部保留。

**v1.2 布局**：游戏名为《X-S战益》，**圆形游戏图标放在四个字的正中间**——「X-S ◎ 战益」，象征左右两边携手合作；副标飘带居中在图标正下方。

**游戏图标**（参考王者荣耀、QQ 飞车的圆形图标：图标内容取自游戏里最高频出现的元素）：
- 外形：粗圆环（破晓渐变，自下而上），顶部留口；
- 内部：一个代码标签 `<♪/>`——左右的「<」「/>」是代码（探索青），中间是音符（米白）；音符的符干与代码的斜杠彼此靠拢、一起向上，音符的符尾伸向代码，像在牵手；
- 顶部：一颗四芒新星（破晓金）冲破圆环开口——共同新生、向上、探索未知；
- 同一个图标用作安卓安装包图标（`CF.Brand.icon()`）。

v1.1 的结构图（标志在最前）保留作为第 3 章小字标的写法：

```
        ·  ·          （上升的像素火花）
  ✦  X-S  战线        ← 标志 + 拉丁（破晓渐变 + 顶面受光 + 扫光） + 中文（米白）
  ╲________________   ← 像素挤出厚度（6 层紫夜，自上而下渐深）
 ━━━━━━━━━━━━━━━━━━   ← 地平线（探索青），破晓辉光从这里升起
        ▛ 造物者之路 ▜  ← 副标飘带（像素台阶边角 + 破晓金顶边）
```

| 要素 | 规则 | 与原宪法的关系 |
|---|---|---|
| 矢量字形 | 「X-S」「战线」等字用 Noto Sans SC Black / Noto Sans Black（SIL OFL 1.1）的轮廓重排，不依赖手机系统字体 | 第 2 章「粗重几何」的落实 |
| 字号关系 | 拉丁大写高度 ≈ 中文字面高度 × 0.9；标志可见高度 ≈ 中文字面高度 × 0.75 | 补充第 3 章 |
| 挤出厚度 | 6 层、每层下移 0.9% 字高，颜色 `#4a2fa0` → `#130b30` 逐层加深；只向正下方 | 第 3 章像素硬投影的延伸（仍是投影，不是描边） |
| 顶面受光 | 拉丁上部 19% 叠一层 `#fff6e0` 0.55 → 0 的高光 | 渐变仍自下而上 |
| 扫光 | 白色光带每 6 秒**自下而上**扫过拉丁与标志一次 | 呼应「向上」；减少动效时关闭 |
| 中文 | 仍为米白 `#ede6d6` 单色，只有厚度，没有渐变与高光 | 第 2 章双色分工不变 |
| 地平线 | 字底下方一条探索青细线，两端渐隐；后方破晓辉光（半椭圆）随节拍增亮 | 第 1 章「-」= 地平线的视觉化 |
| 上升火花 | 6 个像素方块（破晓金 / 探索青）缓慢上升淡出 | 像素与矢量并置 |
| 副标飘带 | 深紫底 + 像素台阶边角 + 破晓金顶边 + 两端菱形；文字米白，字距 0.5em | 新增 |

- 中文部分可替换：`CF.Brand.keyLogo({ cjk: '战益', sub: '造物者之路' })`，或在 `js/config.js` 改 `title`。字形库里没有的字会自动退回系统字体；需要新字时运行 `tools/gen-brand-glyphs.py` 重新导出。
- **禁止**：给主标题加描边或外发光框、倾斜或拉伸字形、把扫光改成左右方向、给中文上色。
- 最小使用尺寸：主标题高度 ≥ 40px；更小时改用第 3 章字标。

# 第二部 · 游戏界面视觉宪法

> 原文件：`art/02-game-ui-constitution.md`

# X-S 游戏界面视觉宪法 v1.5

> 适用于游戏的所有界面、角色、乐器、动效与特效。核心来自参考视频：**紫色像素方格随节拍波动，像素小人抱着乐器演奏**。
> 本宪法已落成代码：`js/pixelfx.js`（像素脉冲舞台）、`js/heroes.js`（英雄与色板）、`js/audio.js`（乐器与节拍）、`css/style.css`（令牌）。

---

## 第 0 章 五条总则

1. **战斗不遮挡**：战斗中 UI 只占屏幕四角，中央全部留给战场。战斗 UI 占比 ≤ 18%（实测：桌面 6–8%，手机横屏 13%）。
2. **点一下就完成**：能用一次点击、长按或拖动完成的操作，不做成按钮。
3. **信息密度随场景变化**：战斗极简；大厅、英雄档案、学院等菜单页把「信息密度」视为正面品质。
4. **节拍即生命**：界面的光、波纹和角色动作都由音乐节拍驱动，静止的界面视为未完成。
5. **像素量化**：所有特效的边缘按 8–12px 的像素网格对齐。矢量只用于文字和品牌标志。

## 第 1 章 招牌动效：像素脉冲舞台

### 1.1 构成（自下而上 5 层）

| 层 | 内容 | 规则 |
|---|---|---|
| 1 底色 | 英雄色板三段渐变（暗 → 中 → 亮，自左向右） | 不出现纯黑或纯白 |
| 2 径向光 | 以角色为中心的柔光 | 不透明度 0.4 + 节拍 × 0.4 |
| 3 像素方格 | 网格亮度分 4 级：0 / 0.34 / 0.56 / 0.8 | 相邻亮级之间不插值，保持阶梯感 |
| 4 角色演奏 | 英雄像素形象 + 乐器 | 见第 5 章 |
| 5 粒子 | 乐器发声点飘出的英雄专属像素粒子 | 每个舞台最多 60 个 |

### 1.2 节拍响应参数

| 事件 | 波速 | 波宽 | 角色动作 | 粒子 |
|---|---|---|---|---|
| 普通拍（强度 < 0.9） | 18 格/秒 | 4 格 | 点头（上移 1 像素）+ 演奏动作 | 1–2 个 |
| 强拍（强度 ≥ 0.9） | 26 格/秒 | 7 格 | 点头 + 前倾 + 50% 概率闭眼 | 3 个 + 1 个灰色双音符 |

- 波纹亮度随时间衰减 e^(−1.3t)，随距离线性衰减到半径上限为 0。
- 无音乐时，用内部时钟按当前 BPM 打拍，动效不停。
- 自定义音乐会实时分析低频能量，检测到重拍才触发强拍。

### 1.3 使用场景与参数

| 场景 | 模式 | 格子 | 说明 |
|---|---|---|---|
| 大厅背景 | full | 28px | 中央展示当前英雄 |
| 页眉条（所有子页面） | bar | 12px | 英雄在右侧演奏；条形波纹呈现视频里的阶梯光带 |
| 弹窗页眉（每个弹窗） | bar | 10px | 同上，缩小版 |
| 模式入口 / 菜单条 | bar | 11px | 悬停或选中时出现，复刻视频里的 Ultracode 条 |
| 英雄卡片、通讯头像 | portrait | 8–10px | 角色居中 |
| 快速模式地面 | 世界网格 | 44px | 从英雄脚下向外扩散，FEVER 时整片发亮 |
| 主城地面 | 世界网格 | 44px | 从城中心呼吸 |
| 技能冲击环 | 世界特效 | 8–12px | 冲击环按像素量化 |
| 全局 CSS | `--beat` 变量 | — | 按钮光晕、页眉阴影、技能按钮外发光随节拍呼吸 |
| 页面切换 | 像素擦除 | 屏宽 ÷ 34 | 420ms，英雄色方块自左向右擦过 |

## 第 3 章 动效系统

| 令牌 | 时长 | 用途 |
|---|---|---|
| `--d1` | 120ms | 悬停、按下反馈 |
| `--d2` | 200ms | 卡片升起、环形菜单弹出 |
| `--d3` | 320ms | 文字上升、气泡、教程卡 |
| 擦除 | 420ms | 页面切换 |

- 缓动：常规 `cubic-bezier(.2,.8,.2,1)`；弹出 `cubic-bezier(.34,1.56,.64,1)`，带轻微回弹。
- **节拍可以影响**：光晕强度、缩放（≤ 12%）、亮度、像素网格。
- **节拍不能影响**：布局位置、文字、可点击区域的大小。
- 环形菜单的按钮依次弹出，间隔 18ms。
- **减少动效**：关闭擦除、波纹降为强拍才触发且强度减半、关闭所有 CSS 动画。

## 第 5 章 角色与乐器

1. **剪影优先**：任何英雄在 16 像素高时仍能一眼认出（鲸是鲸，羊驼是羊驼，团子是团子）。
2. **乐器即武器**：技能名、特效、粒子都来自乐器本身的演奏方式（扫弦、琶音、滑音、击鼓、吹奏、拉弓、轮指、鼓腮）。
3. **演奏动作随节拍**：每位英雄至少有 2 帧演奏动作（如扫弦手上下、琴弓左右、腮帮鼓起），在节拍上切换。
4. **表情**：睁眼 / 闭眼两帧，平时每 2.5–6.5 秒随机眨眼一次，强拍时可能闭眼陶醉。
5. **主题曲动机**：每首主题曲以 8 小节为一循环，第 1、5 小节固定演奏动机（记忆点），其余小节在调式内级进变奏。选英雄、放技能时播放动机前几个音。

## 第 8 章 视觉传达

- **注意力层级**：战场 > 我方英雄 > 敌人 > 资源点 > UI。UI 永远使用半透明玻璃（`rgba(9,7,20,.62)` + 6px 模糊），不与战场争夺注意力。
- **冗余编码**：不只用颜色表达信息。乱码军团用粉青双色错位和抖动字形，选中用绿圈加名牌，状态用图标（眩晕星、护盾圈、月痕点）。
- **图标**：实体（建筑、单位）一律用游戏内像素图标；表情符号只用于技能、导航与物品。

---

## 第 9 章 无障碍与安全

- 文字对比度见《字体美术宪法》第 8 章。
- **光敏安全**：闪屏不透明度 ≤ 0.28，同一位置的闪烁频率 < 3 次/秒；FEVER 的全屏染色不透明度 ≤ 0.14。
- **减少动效**：跟随系统设置，也可在游戏设置中手动开启。
- **休息提醒**：每专注 25 分钟提醒起身远眺、拉伸（体）。

## 第 10 章 四位一体：配色 · 乐器 · 音乐 · 特效

每位英雄的以上四项必须来自同一个意象（例：鲸歌 = 深海蓝 + 古琴 + 低沉滑音与鲸歌 + 气泡与巨鲸）。新增英雄时先写意象，再按意象依次定配色、乐器、动机和粒子。

## 第 12 章 像素图标系统（v1.1 增补）

> 解决「界面里混着系统 emoji，风格不统一」：全游戏只用一套像素图标，实现见 `js/icons.js`。

1. **网格**：12 × 12 格，1 格 = 1 像素单位；图形占中间 10 × 10，四周留 1 格呼吸。
2. **三种颜色**：`#` 主色（跟随文字色 `currentColor`）· `+` 点缀色（当前英雄主光 `--hero`）· `o` 高光（白 90%）。一个图标最多这三种。
3. **线宽**：主体笔画 2 格，细节 1 格；不画描边，靠 1 像素硬投影 `0 1px 0` 从背景里分离。
4. **尺寸**：跟随字号，1.15em；常用 18–24px（导航 18px、任务列表 20px、技能按钮 20px）。只按整数倍放大，`shape-rendering: crispEdges`。
5. **语义**：一个图标只表达一个概念（学院 = 书、实验室 = 烧瓶、档案 = 折线、德 = 心、体 = 哑铃、美 = 吉他……）；技能图标来自技能动作（尺 = 量天一斩、盾 = 护刃、日出 = 新生·向上）。
6. **自动替换**：界面里出现的已登记 emoji 会被自动换成同名像素图标；新增 emoji 前先画图标并登记，否则不得出现在界面上。
7. **禁止**：在 UI 中直接使用系统 emoji；图标里出现渐变、半透明阴影、圆角矢量线。

## 第 22 章 技能释放条件（v1.6 增补，按主创要求「技能不用建造资源」；三个方案试行，待主创确认）

  - ③ **节拍充能**：普攻命中 +1 拍，打在强拍上再 +1，最多存 6 拍；Q / W 用 2 拍，R 用 5 拍（「节拍即生命」，第 0 章）。

# 《造月之路》角色设计宪法 v2.0（原《英雄设计宪法》）

> 适用于所有英雄：设定、技能、数值、像素形象、乐器（法宝）、主题曲、特效、专属小兵与专属建筑。

## 第 0 章 总则

1. **一个意象贯穿到底**：配色、乐器、主题曲、特效、技能、小兵、建筑都来自同一个意象（例：鲸歌 = 深海 + 古琴 + 低沉滑音 + 气泡与巨鲸）。
2. **灵感可借，形象原创**：英雄的性格与能力可以借鉴知名 AI 大模型的公开特点，但名字、形象、标志全部原创，不使用对方的名称、商标与吉祥物；文案里写明「灵感来源」，并声明不代表任何公司。
3. **性格决定机制**：先写性格关键词，再把关键词翻译成技能机制，而不是先想技能再贴性格（见第 3 章）。
4. **乐器是法宝**：每位英雄有且只有一种乐器，一经确定不再更换；乐器是后期才能获得的「法宝」（见第 6 章）。
5. **剪影优先**：任何英雄在战场上 2.4 像素/格的尺寸下，第一眼就能认出是谁。
6. **（v2.0）按吉祥物设计，默认不拟人**：除非主创特别要求，角色用动物、物件、自然现象或它们的混合体来做，不画人类的身体比例、发型和衣服（见第 17 章）。已有的人形角色（造乐、月弦、珠问）保留，以后不再新增。
7. **（v2.0）每个角色必须有一个记忆点**：一个只属于它、缩小了也看得见、能做成动作的特征（例：灯语的「灯眼」强拍时亮起；鲸歌头顶的喷泉）。
8. **（v2.0）配色按情况设计，不套同一个公式**：角色和背景的颜色关系要刻意选择（对比、同色系或无彩衬托），新角色与已有角色拉开色差（见第 17 章第 3、4 条）。

## 第 4 章 技能与数值

### 4.1 技能结构：被动 + Q / W / R

| 槽位 | 作用 | 冷却 | 算力 | 伤害预算 |
|---|---|---|---|---|
| 被动 | 每次攻击或每隔几秒自动触发，体现性格 | — | — | 等效 +15%–35% 输出 |
| Q | 主动输出或位移，最常用 | 8–12 秒 | 30–40 | 单次 100–140（或多段合计） |
| W | 防御 / 支援 / 召唤 / 控制 | 16–20 秒 | 30–40 | 伤害 ≤ 90，或护盾 150–400 |
| R | 终极技能，**需要法宝** | 55–60 秒 | 80–90 | 合计 250–400，或持续 4–10 秒的大范围效果 |

- 目标类型只有三种：`self`（以自身为中心）、`dir`（指向方向）、`point`（指定位置）。
- 技能描述统一写成「动作 + 数值 + 时长」：「向前突进 240 距离，沿途斩击造成 130 伤害并短暂眩晕」。
- 只用效果原语组合：`ring` 冲击环 · `shot` 弹道 · `field` 领域 · `beam` 光束 · `cone` 扇形 · `dash` 突进 · `chain` 连锁 · `buff` 状态 · `later` 延时。新原语要先写进本章。
- 技能等级（沉浸模式）每级 +25% 效果。

### 4.2 属性预算（基础值，沉浸模式每级 +10%）

| 定位 | 耐久 | 每秒伤害（攻击 ÷ 间隔） | 射程 | 移速 |
|---|---|---|---|---|
| 战士（近战） | 780–850 | 40–48 | 40–46 | 108–115 |
| 坦克 | 900–1000（护甲 5） | 18–22 | 150 | 85–90 |
| 法师 / 辅助 | 520–600 | 20–28 | 170–200 | 95–105 |
| 射手 / 刺客 | 480–520 | 24–30 | 200–260 | 100–105 |

近战英雄耐久高、输出高，但必须贴身；远程英雄靠技能和射程。新英雄的每秒伤害不得超过同定位上限。

## 第 5 章 主题曲设计法

1. **8 小节一循环**：第 1、5 小节固定演奏**动机**（记忆点）；第 3–4、7–8 小节在调式内级进变奏，最后一拍回到稳定音。
2. **乐器即音色**：主奏音色就是英雄的乐器（法宝），节奏组按世界观选（锣鼓、手鼓、架子鼓、沙锤……）。
3. **调式表达性格**：

| 情绪 | 调式 | 例 |
|---|---|---|
| 明亮、通用 | 大调 / 宫调 | 万象、团团、X-S（合奏） |
| 好奇、梦幻、探索未知 | 利底亚（升四级） | 双子 |
| 坚韧、叛逆 | 小调五声 / 布鲁斯 | 狂想、羊驼 |
| 深沉、东方 | 羽调、商调 | 月弦、珠问 |

4. **速度表达定位**：坦克 / 法师 66–112 BPM，战士 / 射手 112–150 BPM。
5. **两档强度**：大厅等页面强度 0.5（无鼓或轻鼓），战斗与快速模式强度 1.0（完整鼓组、失真）。
6. **响度**：实测平均 RMS 0.03–0.07、峰值 < 0.75；超出时只改该曲的 `gain` / `gainLo`。
7. **招牌乐句**：动机的前 4–7 个音，用于选英雄、点英雄、放技能。
8. **向上的写法**：最后一段整体升全音，动机在更高处再出现一次（v1.0 起；v1.1 用在合奏主题曲里）。
9. **主角主题曲 = 九乐器合奏**（v1.1，按主创要求）：X-S 的主题曲由全部九位英雄的乐器一起演奏，用来表达「众人一心、共同新生、向上、探索未知」。写法：

| 段落 | 小节 | 写法 | 表达 |
|---|---|---|---|
| ① 新生 | 1–8 | 只有电吉他（主角）独奏动机 | 一个人的起点 |
| ② 相遇 | 9–16 | 电吉他发问；钢琴、竖琴、架子鼓、排箫、古琴、二胡、琵琶、唢呐依次用**各自英雄的动机**回应，回应过的乐器留下来伴奏 | 每个人带着自己的声音加入 |
| ③ 同行 | 17–24 | 节奏（鼓、锣鼓）、低音、和声（钢琴、竖琴、琵琶、古琴）、旋律（电吉他 + 二胡齐奏，唢呐 / 排箫应答）各司其职 | 分工合作 |
| ④ 向上 | 25–32 | 整体升高全音，九件乐器**齐奏同一条动机**，竖琴向上刮奏 | 上下一心 = 齐奏 |

   - 调式选五声音阶（D 宫调）：古琴、二胡、琵琶、唢呐、排箫与钢琴、吉他都能自然演奏，「不同的乐器，同一个调」。
   - 动机 1-2-3-5-6 上行、跃上高音 1、**停在 2**：最后一个音不回到主音，留下「还没说完」的感觉 = 探索未知。
   - 主角的表达：电吉他是唯一贯穿全曲的声部——第一段独奏、第二段发问、第三段与二胡齐奏、第四段领奏；主角不是最响的那个，而是把大家连起来的那个。
   - 分段音量包络：独奏段抬高、齐奏段压低，整首平均 RMS 仍在 0.03–0.07，但听感一路向上。
   - 在 X-S 英雄档案的「合奏分轨」里可以逐件乐器开关、跳到任意段落试听。

## 第 7 章 像素形象

1. **画布**：英雄不超过 22 × 20 格，面朝右；小兵（`drawMinion`）不超过 12 × 10 格。
2. **颜色**：身体 3–5 色 + 乐器 2–3 色 + 描边色 `#1b1226`（只用在乐器与五官，不给全身描边）。
3. **光源**：左上方；暗面色放在身体左侧或下沿。
4. **必备状态**：待机、演奏 / 攻击（`strum`，2 帧在节拍上切换）、眨眼（`blink`）、行走（`walk` + `step`，两脚交替）、强拍探身（`lean`）、受击闪白（`tint`）。
5. **灯语**（v2.0 按主创要求改写；原「X-S 橙色方形小家伙」与 v1.3 的「灯塔帽守灯人」均作废）：橙色的小猫头鹰，圆蛋形剪影，两撮耳羽的尖是新芽绿；**记忆点是一对「灯眼」**——平时米白，强拍时亮成灯黄色并向两侧放光，眨眼时合成一条线；肚皮浅橙带人字羽纹；抱着 v5 原样的紫色电吉他（琴身白色四芒星），扫弦的翅膀随强拍上下摆动。配色保留 v5：身体 `#ec8a5e` / 暗面 `#b85f40`，背景紫 `#22144c → #4a2fa0`。
6. **剪影测试**：缩小到战场尺寸（2.4 像素/格）后，只看轮廓也能认出；与已有英雄的轮廓不能相同。

## 第 13 章补充（v2.0，按主创要求）：语录与「去机械感」配音

1. **语录结构**参考王者荣耀、英雄联盟（只参考结构，台词全部原创）：每位英雄 9 句——选中 `pick`、移动 `move`、攻击 `attack`、大招 `skill`、击杀 `kill`、濒危 `low`、复活 `revive`，加两句点击台词。每句 ≤ 20 字，要有态度、能听出性格，不写说明书式的句子。
2. **什么时候说**：选中 / 点英雄（5 秒冷却）、开始移动（9 秒冷却）、攻击（6 秒冷却）、放大招、击杀（首领、敌方英雄必说，普通敌人约 35%，7 秒冷却）、残血、复活。优先级：大招 > 濒危 = 复活 > 击杀 > 攻击 = 点击 > 移动，低优先级的不会打断正在说的高优先级台词。
3. **演绎**（`tools/gen-voices.py` v2）：一句台词按标点切成短语，每个短语单独定语速、音高、音量——「！」重读、「？」上扬、「……」拖长变弱、「——」短停后加强；按台词类型套情绪模板（大招拔高、压缩、轻微饱和、回声；濒危放慢、压低、发颤、变暗；击杀冷静；复活提气）；大招和濒危前加一口气声。
4. **挑 take**：每句 4 条（整句 / 分句 × 两种语速），先比语音识别的拼音错误率，清晰度相同时选音高起伏更大的那条。
5. 这仍然是语音模型合成的声音，不是真人配音；真人配音的流程见第 13 章补充（v1.3）第 6 条。

## 第 17 章 角色设计：吉祥物标准（v2.0，按主创要求）

> 以美术角色设计师的身份做角色：目标是**让人记住**。参考的是吉祥物设计——形状简单、一眼能认、有一个只属于它的特征、换任何尺寸和场合都成立。

### 1. 先定「记忆点」，再画身体
- 每个角色只有**一个**主记忆点，最好能和节拍一起动（强拍时亮、喷、摆、闪）。记忆点要在 2.4 像素/格的战场尺寸下仍然看得见。
- 已有角色的记忆点：灯语 = 灯眼；鲸歌 = 头顶喷泉；团团 = 冒热气的包子褶；羊驼 = 长脖子与蓬松毛；双子 = 一蓝一粉两个小团子；万象 = 白色机身与琴键牙；狂想 = 朋克刺头；造乐 = 指挥棒与无人机「伏特」。
- 记忆点与性格、乐器是同一个意象（第 0 章第 1 条）。

### 2. 不拟人（除非主创特别要求）
- 用动物、物件、自然现象，或它们的混合（猫头鹰 + 灯塔、鲸 + 古琴、包子 + 唢呐）。
- 不画人类的身体比例、发型、衣服；**乐器由身体部件演奏**：翅膀、鳍、尾巴、蹄子、触角、蒸汽……
- 形状：主体不超过 3 个基本形（圆 / 蛋 / 方 / 三角），细节只放在记忆点上；眼睛要大、能做表情（眨眼、亮起、眯眼）。
- 一个角色 3 种主色以内（身体主色 + 暗面 + 一种点缀），乐器另算 2–3 色。

### 3. 图底关系：按情况选，不套同一个公式
角色（图）和背景（底）的颜色关系有三种做法，**每个新角色都要写明选了哪种、为什么**：

| 做法 | 说明 | 适合 | 例 |
|---|---|---|---|
| **对比**（互补或冷暖相对） | 角色暖、背景冷，或反过来；色相差 ≥ 120° | 想让角色「跳出来」、主角级或吉祥物级角色 | 灯语：橙身（19°）+ 紫底（253°）；团团：米白包子 + 深红底；羊驼：奶油色 + 深蓝底 |
| **同色系**（角色主色 ≈ 背景色） | 色相差 < 40°，必须用明度拉开：角色与背景的明度差 ≥ 30%，并加一圈亮色轮廓光或强对比的记忆点 | 想表达「融入环境」：深海、夜空 | 鲸歌（蓝鲸 + 深海蓝）、月弦（夜色 + 夜空） |
| **无彩衬托** | 背景接近黑 / 灰 / 白，只让角色带颜色；或角色黑白、背景带色 | 性格极端、需要很强的个性 | 狂想：黑白 + 一抹霓虹红 |

- 现状（v2.0 实测，身体主色 vs 背景中间色）：同色系 6 位（双子、鲸歌、月弦、珠问、万象、狂想）、对比 3 位（灯语、羊驼、团团）、造乐介于两者之间。**同色系已经偏多**，接下来的新角色优先考虑对比或无彩衬托。
- 同色系不是不行，但要有理由（「融入」本身是角色的表达），并且满足上面的明度差与轮廓光要求。

### 4. 和已有角色拉开色差（「尽量不撞色」）
新角色在下面三项里，**至少两项**要和每一位已有角色拉开；如果有一项撞色，其余两项必须拉得更开：

| 项 | 拉开的标准 |
|---|---|
| 身体主色 | 色相差 ≥ 30°，或明度差 ≥ 25% |
| 主光色（界面主题色） | 色相差 ≥ 40° |
| 背景中间色 | 色相差 ≥ 30°，或明度差 ≥ 15% |

已有角色的取值（v2.0 实测，HSL 的色相 / 饱和度 / 明度）：

| 角色 | 身体主色 | 背景中间色 | 主光色 | 图底关系 |
|---|---|---|---|---|

# X-S 关卡难度宪法 v1.3

> 你提到「难度等级这些东西不知道怎么描述」——游戏行业的做法是把难度**量化成数字**：给每种敌人一个「威胁值」，给每一关一个「难度等级」，再用公式算出每一波该出多少敌人。这样难度可以预测、可以调、可以复盘。本宪法就是这套规则。
> 已落成代码：`js/chapters.js`（难度生成器、章节、小关、组队副本、奖励）、`js/levels.js`（剧情关）。
> **修订规则**：主创没有明确要求修改时，已定条款一律不改，只增补，并写进文末修订记录。

---

## 第 0 章 四条原则

1. **可度量**：每一波的强度都能算出一个数（威胁值），不靠感觉。
2. **前缓后陡**：一关之内前两波很轻松，让玩家布置经济和防线；最后一波才是考验。
3. **新东西先教再考**：新兵种、新机制第一次出现时更弱、或先送一点帮助。
4. **稀缺的东西才珍贵**：英雄、法宝、碎片只从章节进度和组队副本获得，并限制每天次数。

---

## 第 1 章 名词

| 名词 | 含义 |
|---|---|
| 章节 | 大的进度单元。v1 有两章：第一章「新生」、第二章「向上」 |
| 普通关 | 章节里的主线关卡，每章随机 10–13 个（按存档种子固定），分为次级关和小关 |
| 次级关 | 剧情关（原战役 5 关）：3 波，需要完成对应学习才能解锁，**通关后不可重复挑战** |
| 小关 | 程序生成的关卡：3 波，**可重复挑战**，奖励是长期消耗的补给 |
| 组队副本 | 每章一个：5 波、难度略高，最多 3 位英雄（队友由 AI 控制），每波都有奖励，第 5 波掉英雄碎片，每天 3 次 |
| 活动副本 / 精英副本 | 预留，三个版本之后再做（见第 9 章） |
| 难度等级 D | 一关的强度数值，D1 最简单，v1 最高 D15 |
| 威胁值 | 一个敌人的「危险程度」，乱码虫 = 1 |

## 第 2 章 威胁值

| 敌人 | 威胁值 | 说明 |
|---|---|---|
| 乱码虫 | 1 | 近战小兵 |
| 乱码蝠 | 1.8 | 飞行，地面工事挡不住 |
| 噪声兵 | 2.2 | 远程 |
| 幻觉巨像 | 9 | 重装、溅射 |
| 首领（遗忘者 / 过拟合空母 / 熵之王） | 30 起 | 只在最后一波出现 |

一波的威胁值 = Σ（数量 × 威胁值）。

---

## 第 3 章 难度等级与预算公式

- **满额威胁值**（普通关第 3 波、副本第 4 波）：`预算(D) = 12 × 1.15^(D−1)`
- **敌人耐久倍率**：`1 + 0.025 × (D−1)`（D15 时 ×1.35）
- **难度分档**（界面上的彩色标签）：

| 分档 | D | 颜色 | 目标胜率（标准机器人，见第 8 章） |
|---|---|---|---|
| 入门 | 1–2 | 绿 | 100% |
| 普通 | 3–5 | 青 | ≥ 95% |
| 进阶 | 6–8 | 金 | ≥ 80% |
| 挑战 | 9–11 | 橙 | 约 50% |
| 噩梦 | 12+ | 粉 | < 30% |

## 第 4 章 波次分配（前缓后陡）

| 关卡类型 | 第 1 波 | 第 2 波 | 第 3 波 | 第 4 波 | 第 5 波 |
|---|---|---|---|---|---|
| 普通关（3 波） | 25% | 50% | 100% | — | — |
| 组队副本（5 波） | 30% | 50% | 75% | 100% | 120% + 首领 |

**兵种登场顺序**（新东西先教再考）：
1. 飞行敌人 D ≥ 3 才出现（「空袭」主题关除外）。
2. 巨像 D ≥ 4 才出现，并且只在后半程（≥ 50% 的波次）出现。
3. 被跳过的份额并入乱码虫，总威胁值不变。
4. 剧情关里新机制第一次出现时：首领用「虚弱」版（如第 2 关遗忘者耐久 ×0.45、第 4 关空母 ×0.75），或者预先送防御（第 2 关在上下文节点旁预置 2 座炮塔）。

**节奏**：第 1 波在开局 35–60 秒后到来，波次间隔 32–55 秒；一关 3–4 分钟，副本约 5 分钟。

## 第 8 章 校准：用「标准机器人」实测

**标准机器人**：只造矿机和炮塔（固定 7 个炮位）、英雄自动放 Q/W、不训练部队、不作弊资源。它代表「会基本操作、但不研究兵种」的玩家。每次改公式都要重新跑一遍（脚本思路：生成某难度的小关，跑完统计胜率和主脑剩余耐久）。

v1 实测（每档 3 局）：

| D | 分档 | 满额威胁值 | 耐久倍率 | 胜率 | 平均主脑耐久 |
|---|---|---|---|---|---|
| 1 | 入门 | 12 | ×1.00 | 3/3 | 100% |
| 3 | 普通 | 16 | ×1.05 | 3/3 | 100% |
| 5 | 普通 | 21 | ×1.10 | 3/3 | 100% |
| 7 | 进阶 | 28 | ×1.15 | 3/3 | 100% |
| 9 | 挑战 | 37 | ×1.20 | 3/3 | 100% |
| 11 | 挑战 | 49 | ×1.25 | 3/3 | 100% |
| 13 | 噩梦 | 64 | ×1.30 | 1/3 | 100% |
| 15 | 噩梦 | 85 | ×1.35 | 0/3 | — |

**结论**：前两档符合目标；D9–D11 对机器人偏容易，D13 起陡增。真人玩家的炮塔位置不会这么理想，所以先保留，下一版本用真人数据再细调（已记入 NEXT.md）。

|---|---|---|---|
| **建造格**（本宪法说的「格」） | 64 × 64 世界像素 | 建筑占位、吸附、放置提示 | 放置模式下显示 |
| 导航格 | 40 × 40 世界像素 | 寻路、断崖判定（引擎内部） | 不显示 |

所有地图尺寸、距离都用「格」描述；1 格 = 64 世界像素。

## 第 2 章 占位格

| 占位 | 建筑 |
|---|---|
| 1 × 1（主流） | 矿机、炮塔、屏障、修复站、雷达站、Agent 工坊、无人机空港、全部英雄专属建筑、上下文节点 |
| 2 × 2 | 主脑、乱码主脑 |
| 预留：2 × 1、3 × 3 | 城墙段、大型工事（后续版本） |

- 一个格子只能有一个建筑。建筑半径 ≤ 30 像素的都能放进 1 格；超过的必须用更大的占位。
- 矿机例外：只能放在资源点上，拖到资源点 1.3 格以内会自动吸过去。
- 资源点所在的格子只能放矿机。

## 第 3 章 吸附规则

- 1 × 1：吸到格子中心；2 × 2：吸到格线交点。
- 放置时显示的是**吸附后的位置**，所见即所得。
- 能放置的条件：在地图内、不在断崖上、格子没被占用、在信号覆盖范围内（主脑 5.3 格、其他建筑 4 格、雷达站 7.2 格）、资源够。不满足时虚影变红，放置条显示原因。

## 第 4 章 放置交互（点一下就完成的延伸）

| 步骤 | 触屏 | 鼠标 |
|---|---|---|
| 打开建造菜单 | 长按空地，或点左下「建造」 | 右键空地 / 按住左键半秒 / 按 B |
| 选建筑 | 点环形菜单里的建筑 → 出现虚影；或**按住建筑直接拖到战场上** | 点建筑，或按 1–8 |
| 移动虚影 | 手指在战场上任意处按下拖动；虚影显示在手指上方 48 像素，不被手指挡住 | 虚影跟着鼠标走 |
| 镜头跟随 | 拖到离屏幕边缘 64 像素以内，镜头朝那个方向平移，越靠边越快（最快 620 像素/秒） | 同左 |
| 放置 | 点放置条上的 ✓ | 左键；按住 Shift 连续建造 |
| 取消 | 点 ✕ | 右键或 Esc |
| 缩放 | 放置时仍可双指缩放 | 滚轮 |

## 第 5 章 网格的视觉

- 只在放置模式出现，离开放置模式立刻消失（战场平时保持干净，界面占比规则见《游戏界面视觉宪法》第 6 章）。
- 可建格：紫色细框 + 很淡的填充，随节拍轻微呼吸；被占用的格：暗粉；断崖格不画。
- 虚影：吸附格画实色方块（可放 = 绿 `#6fdc8c`，不可放 = 红 `#ff5d6c`），建筑本体 65% 不透明度，带射程圈的建筑同时显示射程虚线。

## 第 6 章 地图尺寸标准（单位：格）

| 模式 | 宽 × 高 | 世界像素 | 说明 |
|---|---|---|---|
| 小关 | 34 × 20 | 2200 × 1300 | 一屏半，3–4 分钟打完 |
| 剧情关 | 31–47 × 20–28 | 2000–3000 × 1300–1800 | 按剧情需要，单关不超过上限 |
| 组队副本 | 37 × 23 | 2400 × 1500 | 三条进攻路线 |
| 遭遇战 | 44 × 27 | 2800 × 1700 | 随机断崖 |
| 沉浸模式 | 50 × 37 | 3200 × 2400 | 迷雾、野怪、扩张 |
| 上限 | 56 × 40 | 3600 × 2560 | 手机性能与操作距离的上限 |

**布局规则**
1. 横向地图，宽高比 1.5–2.2；我方主脑在左侧，离左边缘 4–6 格；敌方出口在右侧。
2. 主脑 3–9 格范围内至少有 3 个晶片点、2 个语料点。
3. 至少一个宽 3–6 格的峡口，让「在峡口放炮塔」这个基本策略成立。
4. 敌人到主脑的最短路径不少于 20 格（给前两波留出建造时间，配合《关卡难度宪法》前缓后陡）。
5. 断崖不能完全切断路线；每张图至少两条通路。

## 第 7 章 镜头

- 缩放范围 0.4–2.2 倍；开局按屏幕自动选择，保证横屏手机上 1 格 ≥ 26 屏幕像素（手指能点中）。
- 镜头跟随只在拖动虚影时生效，其余时间由玩家自己平移，避免「镜头乱跑」。

## 第 8 章 后续（预留）

- 单位的格子站位（像金铲铲那样把部队拖到格子上布阵）。
- 2 × 1、3 × 3 占位的建筑。
- 断崖与资源点按格子对齐。

## 第 9 章 电路工坊的网格（v1.1 增补）

- 电路板为 **7 × 5 个接线点**；元件放在两个相邻接线点之间的「边」上（横边 6 × 5、竖边 7 × 4），一条边只能放一个元件。
- 拖拽规则与第 4 章一致：按住元件盒里的元件拖到板上，吸附到最近的边，可放绿、被占红；已放的元件可以再拖走；点元件弹出操作（开关 / 换阻值 / 翻转极性 / 拿走）。题目给定的元件不能移动。
- 求解：节点电压法（导线 1e-4 Ω、电流表 0.01 Ω、电压表 10 MΩ、电池内阻 0.05 Ω、二极管正向压降 2 V），每帧实时计算；电池电流超过 8 A 判定为短路。


## 第 10 章 电路工坊的点选放置（v1.2 增补，按主创要求）

- 参考植物大战僵尸：**点一下元件盒里的元件 = 选中**（卡片上浮、绿色描边，所有空边一起微微发绿），**再点电路板上的空边 = 放下**。拖拽放置照旧可用，两种方式随便混用。
- 选中后可以连续放：还有库存就保持选中；用完自动取消。
- 取消选中：再点一次同一张卡片、点电路板上离边太远的空白处、鼠标右键或 Esc。
- 点到已经有元件的边：提示「这条边已经有元件了」，不放、保持选中。
- 鼠标悬停时显示半透明虚影（可放绿、被占红），触屏没有悬停，靠「空边发绿」提示能放的位置。


## 第 11 章 电路工坊：模块、大电路板与镜头（v1.3 增补，按主创要求）

- 电路板大小随实验变化：基础电路 7 × 5；**具身智能模块 9 × 6**；**航空航天模块、自由搭建 11 × 7**。元件仍放在两个相邻接线点之间的边上，边的编号与板子大小无关，所以旧的自由搭建存档在大板上照样能用。
- **两种镜头**：固定镜头（默认，整块电路板正好放进画面，不能缩放、平移）；自由镜头（滚轮、双指捏合、右上角 ＋ / － 缩放 0.6–3.2 倍；拖动空白处平移）。在固定镜头下缩放会自动切到自由镜头；点「固定镜头」一键回到全图。缩放后吸附判定、点选放置照样准确。
- 新元件：电机（正常 8 Ω，堵转 1 Ω，转速动画随电流）、二极管（0.7 V）、保险丝（0.5 / 1 / 2 / 10 A，超过额定电流熔断，每次熔断电流最大的一根再重算）、太阳能板（诺顿等效：短路电流 0.5 A × 光照，并联 18 Ω）、光敏电阻（亮 200 Ω → 暗 10 kΩ）。
- 两个新模块都**从高中难度开始**、每个模块单独顺序解锁：具身智能 6 关（电机、电池串联、左右轮并联、光敏传感器、H 桥正反转、堵转保护），航空航天 5 关（太阳能信标灯、卫星配电母线、防反充二极管、冗余供电二极管或门、分区保护）。

## 第 12 章 电路工坊：取消、答案讲解、新元件、大画布、文字解析、部件收集（v1.4 增补，按主创要求）

**12.1 取消与答案**
- 点选元件后放到板上，**再点一次板上已经放好的元件 = 拿掉**（关卡自带的固定元件不能拿掉）。
- 同一关**检验失败 4 次**，自动弹出「讲解」：目标、怎么接、为什么（原理）、再往深一层，有小测验的关卡附小测验。可以一键「摆出正确答案」，看清电流怎么走后再点「检查」完成实验；这样完成的奖励减半。

**12.2 新元件（满足具身智能、航空航天的基本需求）**

| 元件 | 模型 | 用途 |
|---|---|---|
| 电位器 | 10 kΩ，旋钮 0 / 25 / 50 / 75 / 100 %（最小 10 Ω） | 调速、调光、给传感器分压 |
| 热敏电阻（NTC） | 10 kΩ @ 25 ℃，B = 3950，温度 0 / 25 / 60 / 100 ℃ 可调 | 电池 / 电机过热检测 |
| 蜂鸣器 | 40 Ω，电流 > 20 mA 响 | 报警 |
| 稳压二极管 | 正向 0.7 V，反向击穿 5.1 V | 保护 5 V 传感器接口 |
| 继电器（线圈 + 触点） | 线圈 60 Ω，电流 > 40 mA 时**同一通道**的触点吸合 | 小电流控制大电机 |
| MOSFET 开关 | 同一通道的单片机输出高电平时导通（0.05 Ω） | 单片机驱动大负载 |
| 单片机 | 150 Ω，两端电压 > 3 V 才运行；四个「小程序」：常亮、闪烁、天黑开灯（读同通道光敏电阻）、过热报警（读同通道热敏电阻） | 「元器件 + 小程序」的最小闭环 |

- 控制关系靠**通道**（A / B / C）配对：线圈 ↔ 触点、单片机 ↔ MOSFET、单片机 ↔ 传感器。解算顺序：先解电路 → 更新触点 / MOSFET 状态 → 再解，直到稳定（和二极管、稳压管、保险丝的状态一起迭代，最多 14 轮）。
- 新关卡：具身智能第 7 关「继电器：小电流控制大电机」、第 8 关「天黑自动开灯：单片机小程序」；航空航天第 6 关「稳压管保护传感器接口」。

**12.3 自由画布**
- 自由搭建的电路板从 11 × 7 扩大到 **17 × 11**，能同时摆多个子电路（电源 + 控制 + 负载 + 保护）。旧存档的元件位置不变。

**12.4 文字解析成电路（本地运行，不联网）**
- 在电路工坊点「解析电路」，输入一句话（例：「9V 电池串联开关和 100Ω 电阻，再并联两个灯泡和一个电机」），本地规则解析出：元件（关键词 + 数量 + 数值）、串联 / 并联关系，自动排版（电源竖放在最左，上下两条母线，串联元件放在上母线上，并联支路竖放在两条母线之间）。
- 两种玩法：「直接搭好」（变成一块可以继续改的自由画布）；「变成题目」（电源和负载固定，导线和开关留给玩家连，参考答案的读数由解算器先算好）。
- 目前**只认文字**；上传电路图照片需要图像识别模型，留到以后（见 `design/07-advisor-review.md`）。

**12.5 电路 → 部件（具身智能 / 航空航天的「零件收集」）**
- 每一关对应一个真实部件：具身智能 8 关 → 机器人 8 个部件（关节电机、电池包、左右驱动轮组、巡线视觉传感器、H 桥电机驱动板、过流保护模块、继电器功率控制板、智能感知主控板）；航空航天 6 关 → 卫星 6 个部件（信标灯、配电单元 PDU、太阳翼充电控制器、冗余电源模块、分区保护熔断盒、稳压传感器接口）。**通关这一关的电路 = 得到这个部件**。
- 「装配图」显示机器人 / 卫星的部件格子（已得 / 未得），点部件看它的**完整工艺流程**：元器件 → 电路原理 → 小程序 → 制作 → 组装 → 调试，每一步写清做什么、注意什么。
- 以后的「真实组装游戏」用这些部件作为输入（部件 id 永不更改，见《物品宪法》第 2 章）。

# 第六部 · 物品宪法

# 《造月之路》物品宪法 v1.0

> 适用于游戏里所有「东西」：资源、英雄战斗资源、养成材料、道具、耗材、收藏品，以及以后的英语田园作物、菜品、装扮。
> 已落成代码：`js/items.js`（物品登记表 + 说明卡 + 物品图鉴）。点战斗里的资源数字、点大厅右上角的仓库都能看到说明。
> **修订规则**：主创没有明确要求修改时，已定条款一律不改，只增补，并写进文末修订记录。

---

## 第 1 章 五条总则

1. **每样东西都要讲得清**：叫什么、长什么样、从哪来、干什么用、有什么限制——五件事缺一不可（第 2 章）。
2. **有来处，就要有去处**：每一种产出都必须有消耗（「水龙头」和「下水道」成对出现），避免资源越攒越多、失去意义。
3. **稀缺的东西靠努力，不靠运气**：英雄、法宝按「集齐碎片」解锁，不做纯随机抽取；有随机的（法宝锦囊）必须公示概率。
4. **不卖真实货币**：所有商品只用游戏里赚到的资源购买。将来如要接入付费，先修改本宪法并完成合规（见 `design/03-compliance.md`）。
5. **世界观一致**：名字和描述都来自「乱码潮 · 音乐把噪声变回信号 · 造月」这个世界；同一样东西全游戏只用一个名字。

## 第 2 章 登记表（每个物品的必填字段）

| 字段 | 说明 | 例（晶片） |
|---|---|---|
| `id` | 小写英文，永不更改（存档引用） | `chip` |
| 名称 | 2–6 个字，全游戏统一 | 晶片 |
| 图标 | 《游戏界面视觉宪法》第 12 章的像素图标，或资源菱形 | 金色菱形 |
| 类别 | 资源 / 英雄 / 养成 / 道具 / 耗材 / 收藏 / 沉浸道具（以后：作物、菜品、装扮） | 资源 |
| 稀有度 | 普通（灰蓝）/ 稀有（青）/ 史诗（紫）/ 传说（金） | 普通 |
| 世界观 | 一句话：它在这个世界里是什么 | 乱码潮退去后留下的硅晶碎片…… |
| 获取渠道 | 至少 1 条，写清楚在哪里、怎么拿 | 矿机采集、赏金、关卡奖励…… |
| 作用 | 至少 1 条 | 建造、训练、商城 |
| 规则 | 上限、有效期、是否带出战斗、转换关系、概率 | 仓库上限 8000 + 1500 × 实验数 |

新物品**先登记、再进游戏**：在 `js/items.js` 加一行，并在第 4 章表格里补一行。

## 第 3 章 分类与规则

| 类别 | 定义 | 关键规则 |
|---|---|---|
| 资源 | 战斗和主城通用的「钱」 | 战斗内无上限；主城仓库有上限；三种资源分工明确：晶片 = 通用，语料 = 高级单位与科技，算力 = 主脑与研究 |
| 英雄 | 英雄在战斗里自带的条（能量 / 节拍） | 只在战斗内存在，不带出战斗；**不与建造资源混用**（v8 起技能不再消耗算力） |
| 养成 | 长期积累、让账号变强的东西 | 不会过期；碎片的去向必须明确（解锁 → 升星 → 满星换晶片） |
| 道具 | 可以打开 / 兑换的东西 | 随机内容公示概率；只用游戏内资源购买；每日限购 |
| 耗材 | 一次性使用、按场景发放的东西（元器件） | 只在当前实验 / 关卡里有效，离开就收回 |
| 收藏 | 图鉴类、永久拥有的东西 | 收集齐了给小幅加成，重复获得换成资源 |
| 沉浸道具 | 沉浸模式一局内的装备 | 物品栏 4 格；不带出战斗 |

**稀有度颜色**：普通 `#c9d4ff` · 稀有 `#4ef0ff` · 史诗 `#b48cff` · 传说 `#ffd257`（与英雄主光色错开，见《角色设计宪法》第 17 章）。

## 第 6 章 英语田园的物品（v1.1 增补）

英语田园（`farm/`，原「生而向星」，见 `design/06-english-farm.md`）有自己的一套物品，**这一版和主游戏的资源互不相通**，所以不在 `js/items.js` 登记，由田园自己的商店、指南、课程页说明。

| 物品 | 获取 | 作用 | 规则 |
|---|---|---|---|
| 金币 | 每日任务（来到田园、收获、做菜、接待客人）、成长路线免费奖励、小馆客人付款、课程快速练习（按星数给） | 买种子、开垦土地、买食材 | 只在田园里用；新存档 0 |
| 星屑 | 每日任务、成长路线的进阶奖励 | 在星光集市兑换装扮、纪念品 | 只在田园里用；新存档 120 |
| 星币（演示） | 新存档自带 1000 | 星光集市的演示商品 | **本机演示货币，不是真钱**；田园编辑器写明「在线支付需要另接服务」——按第 1 章第 4 条，不接入真实支付。成长路线分「免费 / 进阶」两条，结构像通行证，将来如果收费必须先改本宪法并完成合规 |
| 种子 / 作物 / 菜品 / 食材 | 商店、收获、厨房 | 种地 → 收获 → 做菜 → 小馆卖出（每样都带英文单词和发音） | 田园内循环，有来处有去处（第 1 章第 2 条） |
| 装扮 / 纪念 | 星光集市 | 换场景物件、作物外观、头像 | 永久 |

**和主游戏的唯一连接**：田园里的学习时间计入主游戏的学习计时（连续 25 分钟 / 零散 40 分钟换无限体力，见 `js/stamina.js`）。
**以后要互通时**（待主创决定）：先在 `js/items.js` 登记、写清兑换比例和每日上限，再接入；学习类奖励要比战斗更有吸引力（第 5 章最后一条），但不能让田园变成刷晶片的地方。

**第 6 章补充（v1.2）**：游戏里的英语田园已换成「豆豆的田园厨房」（第 27 版）。它的物品是金币、种子、作物、菜品、鸡蛋、装扮；上表里的星屑、星币（演示）和「免费 / 进阶」成长路线属于已移除的旧版「生而向星」，不再出现在游戏里。种子在农场里做成了种子卡牌（拿着 = 发亮，没有 = 变暗，点它去种子店），规则同第 3 章「道具」类。和主游戏的唯一连接仍是学习计时。
