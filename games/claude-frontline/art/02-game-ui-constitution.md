# X-S 游戏界面视觉宪法 v2.5

> 适用于游戏的所有界面、角色、乐器、动效与特效。核心来自参考视频：**紫色像素方格随节拍波动，像素小人抱着乐器演奏**。
> 本宪法已落成代码：`js/pixelfx.js`（像素脉冲舞台）、`js/heroes.js`（英雄与色板）、`js/audio.js`（乐器与节拍）、`css/style.css`（令牌）。

---

## 第 0 章 五条总则

1. **战斗不遮挡**：战斗中 UI 只占屏幕四角，中央全部留给战场。战斗 UI 占比 ≤ 18%（实测：桌面 6–8%，手机横屏 13%）。
2. **点一下就完成**：能用一次点击、长按或拖动完成的操作，不做成按钮。
3. **信息密度随场景变化**：战斗极简；大厅、英雄档案、学院等菜单页把「信息密度」视为正面品质。
4. **节拍即生命**：界面的光、波纹和角色动作都由音乐节拍驱动，静止的界面视为未完成。
5. **像素量化**：所有特效的边缘按 8–12px 的像素网格对齐。矢量只用于文字和品牌标志。

## 第 1 章 招牌动效：像素脉冲舞台

### 1.1 构成（自下而上 5 层）

| 层 | 内容 | 规则 |
|---|---|---|
| 1 底色 | 英雄色板三段渐变（暗 → 中 → 亮，自左向右） | 不出现纯黑或纯白 |
| 2 径向光 | 以角色为中心的柔光 | 不透明度 0.4 + 节拍 × 0.4 |
| 3 像素方格 | 网格亮度分 4 级：0 / 0.34 / 0.56 / 0.8 | 相邻亮级之间不插值，保持阶梯感 |
| 4 角色演奏 | 英雄像素形象 + 乐器 | 见第 5 章 |
| 5 粒子 | 乐器发声点飘出的英雄专属像素粒子 | 每个舞台最多 60 个 |

### 1.2 节拍响应参数

| 事件 | 波速 | 波宽 | 角色动作 | 粒子 |
|---|---|---|---|---|
| 普通拍（强度 < 0.9） | 18 格/秒 | 4 格 | 点头（上移 1 像素）+ 演奏动作 | 1–2 个 |
| 强拍（强度 ≥ 0.9） | 26 格/秒 | 7 格 | 点头 + 前倾 + 50% 概率闭眼 | 3 个 + 1 个灰色双音符 |

- 波纹亮度随时间衰减 e^(−1.3t)，随距离线性衰减到半径上限为 0。
- 无音乐时，用内部时钟按当前 BPM 打拍，动效不停。
- 自定义音乐会实时分析低频能量，检测到重拍才触发强拍。

### 1.3 使用场景与参数

| 场景 | 模式 | 格子 | 说明 |
|---|---|---|---|
| 大厅背景 | full | 28px | 中央展示当前英雄 |
| 页眉条（所有子页面） | bar | 12px | 英雄在右侧演奏；条形波纹呈现视频里的阶梯光带 |
| 弹窗页眉（每个弹窗） | bar | 10px | 同上，缩小版 |
| 模式入口 / 菜单条 | bar | 11px | 悬停或选中时出现，复刻视频里的 Ultracode 条 |
| 英雄卡片、通讯头像 | portrait | 8–10px | 角色居中 |
| 快速模式地面 | 世界网格 | 44px | 从英雄脚下向外扩散，FEVER 时整片发亮 |
| 主城地面 | 世界网格 | 44px | 从城中心呼吸 |
| 技能冲击环 | 世界特效 | 8–12px | 冲击环按像素量化 |
| 全局 CSS | `--beat` 变量 | — | 按钮光晕、页眉阴影、技能按钮外发光随节拍呼吸 |
| 页面切换 | 像素擦除 | 屏宽 ÷ 34 | 420ms，英雄色方块自左向右擦过 |

## 第 3 章 动效系统

| 令牌 | 时长 | 用途 |
|---|---|---|
| `--d1` | 120ms | 悬停、按下反馈 |
| `--d2` | 200ms | 卡片升起、环形菜单弹出 |
| `--d3` | 320ms | 文字上升、气泡、教程卡 |
| 擦除 | 420ms | 页面切换 |

- 缓动：常规 `cubic-bezier(.2,.8,.2,1)`；弹出 `cubic-bezier(.34,1.56,.64,1)`，带轻微回弹。
- **节拍可以影响**：光晕强度、缩放（≤ 12%）、亮度、像素网格。
- **节拍不能影响**：布局位置、文字、可点击区域的大小。
- 环形菜单的按钮依次弹出，间隔 18ms。
- **减少动效**：关闭擦除、波纹降为强拍才触发且强度减半、关闭所有 CSS 动画。

## 第 5 章 角色与乐器

1. **剪影优先**：任何英雄在 16 像素高时仍能一眼认出（鲸是鲸，羊驼是羊驼，团子是团子）。
2. **乐器即武器**：技能名、特效、粒子都来自乐器本身的演奏方式（扫弦、琶音、滑音、击鼓、吹奏、拉弓、轮指、鼓腮）。
3. **演奏动作随节拍**：每位英雄至少有 2 帧演奏动作（如扫弦手上下、琴弓左右、腮帮鼓起），在节拍上切换。
4. **表情**：睁眼 / 闭眼两帧，平时每 2.5–6.5 秒随机眨眼一次，强拍时可能闭眼陶醉。
5. **主题曲动机**：每首主题曲以 8 小节为一循环，第 1、5 小节固定演奏动机（记忆点），其余小节在调式内级进变奏。选英雄、放技能时播放动机前几个音。

| 英雄 | 乐器音色实现 | 调式 | BPM | 动机 |
|---|---|---|---|---|
| X-S | **九乐器合奏**：电吉他领奏，钢琴、竖琴、架子鼓、排箫、古琴、二胡、琵琶、唢呐与锣鼓依次加入（v1.2 按主创要求） | D 宫调，最后八小节升全音 | 116 | 1-2-3-5-6 上行跃上高音 1、停在 2 |
| 万象 | 加法合成钢琴（4 个泛音 + 击弦噪声） | C 大调 | 100 | 5-3-1-3-5-8 |
| 双子 | 明亮长余音拨弦 + 滑音刮奏 | D 利底亚 | 88 | 双声部一问一答 |
| 狂想 | 架子鼓、筒鼓加花、失真贝斯 | E 布鲁斯 | 150 | 切分鼓点 |
| 羊驼 | 正弦 + 气声排箫，查朗戈扫弦 | A 小调五声 | 112 | 5-3-2-1 牧歌下行 |
| 鲸歌 | 低沉拨弦 + 滑音 + 泛音，鲸歌长音 | C 宫调 | 66 | 古琴滑音 |
| 月弦 | 锯齿波 + 共振峰 + 颤音 + 滑音（二胡） | A 羽调 | 72 | 长弓滑音下行 |

## 第 6 章 界面密度与布局

### 6.1 战斗（≤ 18%）

```
┌ 资源 · 人口 ┐         波次 · 计时 · 目标一行          ┌ 研究 暂停 速度 地图 菜单 ┐
└ 双方主脑   ┘                                         └ 小地图（手机默认收起）   ┘
  通讯（4.6 秒后自动隐藏）
                       （ 中 央 全 部 是 战 场 ）
┌ 建造 ┐┌ 全军 ┐ 已选 12 · …                       物品  ( 头像 ) (Q)(W)( R )
```

- 选中信息不用面板，改为单位头顶的浮动名牌和左下的一行选中条。
- 训练、拆除等建筑操作以环形菜单绕在建筑周围，只在选中时出现。
- 手机上 HUD 整体缩放到 85%（参考米哈游移动端适配）；触控目标 ≥ 44px（技能 56–68px，环形按钮 58px）。

### 6.2 大厅（功能枢纽，信息密度高）

- 左上：字标 + 个人信息；右上：主城资源 + 说明 + 设置。
- 中央偏左：当前英雄（可左右切换，点击会演奏并说口头禅）。
- 右侧：玩法入口做透视倾斜（rotateY −14°，参考 QQ 飞车），把空间让给英雄；其上方是今日修炼等活动卡。
- 底部：导航（英雄、主城、学院、实验室、档案、成就、设置、说明）。

### 6.3 菜单页

英雄档案、学院、档案页可以高密度呈现信息：属性、技能数值、色板、故事都展示出来，并用标签页分组。

## 第 7 章 交互：点一下就完成

| 手势（触屏 / 鼠标） | 结果 |
|---|---|
| 点（左键） | 选中；已选部队时：点地面移动（沿途自动攻击）、点敌人集火；点空资源点：弹出「矿机」 |
| 双击 | 选中屏幕内同类单位；双击空地取消选择 |
| 长按松手（右键空地） | 在该点弹出环形建造菜单 |
| 长按后拖动（左键拖动） | 框选 |
| 拖动（右键 / 中键拖动） | 平移视野 |
| 双指（滚轮） | 缩放 |
| 技能按钮 | 自身技能点按释放；方向和位置技能按住拖到目标处松手，或先点按钮再点战场（电脑 Q/W/R 对准鼠标位置立即释放） |

**反馈规则**：每个操作在 100ms 内同时给出视觉反馈（点击波纹、按钮缩放）和声音反馈（短促提示音或乐句）。

## 第 8 章 视觉传达

- **注意力层级**：战场 > 我方英雄 > 敌人 > 资源点 > UI。UI 永远使用半透明玻璃（`rgba(9,7,20,.62)` + 6px 模糊），不与战场争夺注意力。
- **冗余编码**：不只用颜色表达信息。乱码军团用粉青双色错位和抖动字形，选中用绿圈加名牌，状态用图标（眩晕星、护盾圈、月痕点）。
- **图标**：实体（建筑、单位）一律用游戏内像素图标；表情符号只用于技能、导航与物品。

---

## 第 9 章 无障碍与安全

- 文字对比度见《字体美术宪法》第 8 章。
- **光敏安全**：闪屏不透明度 ≤ 0.28，同一位置的闪烁频率 < 3 次/秒；FEVER 的全屏染色不透明度 ≤ 0.14。
- **减少动效**：跟随系统设置，也可在游戏设置中手动开启。
- **休息提醒**：每专注 25 分钟提醒起身远眺、拉伸（体）。

## 第 10 章 四位一体：配色 · 乐器 · 音乐 · 特效

每位英雄的以上四项必须来自同一个意象（例：鲸歌 = 深海蓝 + 古琴 + 低沉滑音与鲸歌 + 气泡与巨鲸）。新增英雄时先写意象，再按意象依次定配色、乐器、动机和粒子。

## 第 12 章 像素图标系统（v1.1 增补）

> 解决「界面里混着系统 emoji，风格不统一」：全游戏只用一套像素图标，实现见 `js/icons.js`。

1. **网格**：12 × 12 格，1 格 = 1 像素单位；图形占中间 10 × 10，四周留 1 格呼吸。
2. **三种颜色**：`#` 主色（跟随文字色 `currentColor`）· `+` 点缀色（当前英雄主光 `--hero`）· `o` 高光（白 90%）。一个图标最多这三种。
3. **线宽**：主体笔画 2 格，细节 1 格；不画描边，靠 1 像素硬投影 `0 1px 0` 从背景里分离。
4. **尺寸**：跟随字号，1.15em；常用 18–24px（导航 18px、任务列表 20px、技能按钮 20px）。只按整数倍放大，`shape-rendering: crispEdges`。
5. **语义**：一个图标只表达一个概念（学院 = 书、实验室 = 烧瓶、档案 = 折线、德 = 心、体 = 哑铃、美 = 吉他……）；技能图标来自技能动作（尺 = 量天一斩、盾 = 护刃、日出 = 新生·向上）。
6. **自动替换**：界面里出现的已登记 emoji 会被自动换成同名像素图标；新增 emoji 前先画图标并登记，否则不得出现在界面上。
7. **禁止**：在 UI 中直接使用系统 emoji；图标里出现渐变、半透明阴影、圆角矢量线。

### 26.1 五条规则（以后所有界面都适用）

1. **框定下来就不动**：一个框（面板、说明框、色卡框、列表框）的位置和大小由版面决定，之后内容变多、变少都不改框。例：实验室顶部的说明框「美也是一种能力……」和 v8 一样大、一样的位置（实测：竖屏 390 宽时 64px 高，360 宽时 84px 高，横屏 43px 高，新旧完全相同）。
2. **放不下时只改框里的排版**，按这个顺序用：
   1. **分类**：加一排分类页签，一次只显示一类（色卡：全部 / 基础 / 品牌·资源·状态 / 英雄；素材：英雄 / 单位 / 建筑 / 图标 / 特效 / 我的）。页签后面用小字写这一类有几个。
   2. **框内滑动**：一排一排的东西（色块、页签）在框里左右滑，一张一张的卡片（素材）在框里上下滑；还有内容没露出来的那一侧淡出 22px，提示「还有」；切换分类后，选中的页签自动滑到中间。
   3. **缩小格子**：手机横屏（高度 ≤ 520px）时色块 28px → 24px、按钮 30px → 26px，框不变。
   4. **收起次要信息**：更矮的横屏（高度 ≤ 400px）收起「当前颜色」一行和预览（选中的色块本身有白框，不会丢信息）。
   5. **兜底**：以上都用完还放不下（极少见的小屏），框里整体上下滑。**不允许裁掉、溢出框外或叠在别的东西上。**
3. **不遮挡**：编辑类界面（像素工坊、电路工坊这类要一直看着画布的地方）的提示不用浮在上面的气泡，**写进顶部说明框本身**：框高先锁成原来的高度，提示显示 2.6 秒后换回说明文字。画布永远不被任何面板、提示、弹层盖住。
4. **空间利用率**：框里剩下的空间要放有用的东西，不留大片空白。例：横排时「画笔与色卡」框下面放整数倍缩放的预览（像素不糊），写「用了几种颜色、能得几星」；剩下不够 48px 高就不显示。
5. **一排按钮必须放得下**：工具按钮平分整排宽度，分段按钮（16 / 64 / 256 / ∞、24 / 64）平分剩下的宽度；框窄于 250px 时，「画布」「色卡」这类文字标签收起（按钮自带悬停说明）。

**验收**：竖屏 390×844、360×740，横屏 844×390、740×360，桌面 1280×800 五种尺寸下，每个框里的按钮、色卡、画布都不出框、不被裁、不重叠，说明框高度和旧版一致（Playwright 实测）。

### 26.2 色卡框：比原来多一行（v2.0 起由 26.8 取代）

- v8 的 16×16 画板，色块排 2 行。v9 起色卡框**固定 3 行高**（3 × 28px 加间距），色块按列排。
- 颜色多了**不再加行**，在框里左右滑（见 26.1 第 2 条）。

1. 每个颜色的编号永不改动（作品按编号存颜色）。以后加颜色只能追加在最后。0 号永远是透明。

3. 从 64 色切回 24 色时，画里用到的英雄色自动换成 24 色里最接近的颜色，记进撤销，点 ↶ 能换回来。

### 26.9 v2.1 增补：上传最高 4K、造月 256 色（主创要求）

> 主创原话：「上传功能像素增加到最高支持 4K，颜色也增加一个行业最高支持色。」

**1. 造月 256 色。**
- 256 是索引色的行业上限：GIF、PNG-8 和专业像素软件的索引模式都是 256 个颜色位。我们的做法是 0 号透明，加 255 个颜色。
- 1–64 号就是 26.3 的造月 64 色。65–255 号全部从这 64 色派生：
  - 暗部往冷色（蓝紫）偏，亮部往暖色（黄）偏，这是像素画调色的通行做法；
  - 再加降饱和的「灰」版本；
  - 超出 sRGB 的降饱和拉回；
  - 任意两色的 OKLab 距离都不小于 0.03，避免出现分不清的颜色。
- 生成器是 `tools/gen-palette256.mjs`，结果写死在 `js/palette.js`。编号永不改动，26.3 第 1 条铁律同样适用。
- 每个色派生出的颜色叫「原名·暗 / 亮 / 灰 / 深 / 浅」，例如「破晓·橙·暗」。
- 调色盘的分段按钮是 24 / 64 / 256。256 色同样按 10 个色系分类，每个色系从暗到亮排。

| 色系 | 灰阶 | 红 | 橙 | 肤色·大地 | 黄·金 | 绿 | 青 | 蓝 | 紫 | 粉 |
|---|---|---|---|---|---|---|---|---|---|---|
| 256 色里的数量 | 24 | 26 | 19 | 23 | 16 | 28 | 25 | 32 | 39 | 23 |

**2. 上传最高 4K。**
- 「上传」里可以选分辨率：跟随画布、256、512、1024、2K（2048）、4K（最长边 4096），还可以选换成 24 / 64 / 256 哪套色卡。
- 选了分辨率，就按图片比例新建画布；比原图大时不放大。3840×2160 的 4K 照片按原尺寸换色。
- 实测：一张 3840×2160 的照片带抖动换成 256 色，大约 1 秒。
- 做法：
  - 图片按 128 行一条分条读取，不一次申请整张图的内存；
  - 最近色用查表（每通道 6 位，用到才算）；
  - 抖动只保留两行误差；
  - 换色时界面显示进度，不卡死。

**3. 大图的保存。**
- 超过 512×512 的画（草稿和作品）存在本机浏览器的 IndexedDB 里，存档里只放一个指针；作品另外带一张 64×64 缩略图。这样存档不会超过浏览器 5MB 的上限而整个存不进去。
- 重新打开工坊时会自动载入上次的大图，载入完成之前不会自动保存，以免把大图覆盖掉。

**4. 大图的显示和操作。**
- 缩得很小、一屏要画几百块时，改画一张最长边不超过 1024 的缩略层，放大回来再一块一块画。
- 「适合」可以缩到 0.02 倍，4K 也能整张放进视野。
- 整张图的操作（清空、换色卡）用前后两份快照撤销。
- 填充一次最多 30 万格，超过的再点一下接着填。
- 换画布尺寸时按块搬，4K 也很快。
- 导出 PNG 时先按块填像素，再整体放大。

**5. 抽屉不遮挡（修正 26.8 第 4 条的摆放）。**
- 横屏时，右侧抽屉从顶行下面开始，右上角的「素材 / 上传 / 保存 / ?」始终露在外面。
- 大屏横屏时，素材库抽屉放在常驻色板的左边，不盖住色板。

### 26.10 v2.2 增补：真彩模式（主创要求「需要不受限的」）

- **例外条款**：像素工坊新增第 4 套色卡「真彩」，可选 1677 万色（24 位 RGB）加透明，**不受造月色卡限制**。这是对 26.3「颜色只能来自造月色卡」的明确例外，经主创要求设立。24 / 64 / 256 三套色卡和它们的规则不变。
- **入口**：调色盘的分段按钮是 24 / 64 / 256 / 真彩；上传里的色卡也可以选「真彩」。
- **调色盘**：真彩时调色盘最上面是「任意色」取色器；下面的造月 256 色可以当快捷色用。
- **上传**：选真彩时，图片颜色原样保留，不做抽抖动。实测 3840×2160 约 0.7 秒。
- **存法**：每格存 `0xFFRRGGBB`（一定大于 255），和色卡编号（1–255）不会重叠，所以全部工具都能共用（画、填、吸、撤销、换尺寸、导出）。
  - 超过 128×128 的真彩图存 IndexedDB，每格 4 字节。
  - 小图在存档里按「是否不透明 · R · G · B · 次数」每段 5 字节编码。
- **互相转换**：
  - 真彩 → 色卡：每个颜色换成目标色卡里最接近的颜色；
  - 色卡 → 真彩：把编号还原成颜色。
  - 两个方向都用整张图快照进撤销。
- **用途**：真彩画的东西可以存作品、设为头像、技能特效，也可以存进衣柜当「我的外观」，颜色原样保留。
- **不受影响的部分**：官方美术（英雄、炫彩皮肤、界面）仍按造月色卡。

### 27.13 接线板（电路图式）规范（v2.3 增补）

- **零件**：圆角方块，中间写名字，点名字看说明。
- **接口**：圆点，颜色就是类型，图例在接线板上方，点图例看这种类型是干什么的。
  - 电源三档：24V 橙红、12V 橙、5V 浅金；
  - 总线：CAN 紫、USB 青、网口 青绿、串口 绿、I²C 黄绿、Wi-Fi 蓝；
  - 软件消息：图像、位姿、音频、文字、动作块……各有固定颜色，见 `js/embodied-data.js` 的 TYPES。
- **连线**：
  - 点一个口、再点另一个口就连上；也可以按住拖过去（和左侧建造栏的「点放 / 拖放」一致）；
  - 一个口只连一根线，新连的替换旧的；
  - 线的颜色跟着接口类型，点线可以拆掉。
- **类型不对接不上**：立刻说明原因。电源类写「电压不一样，真机上会直接烧坏」，其他类型写「插头插不进，数据也读不懂」。记一次失误。
- **检查**：
  - 接错的线变成红色虚线，同时提示「它本该连到哪、为什么」；
  - 「提示」让两个该连的口发光，并说明理由；
  - 通关后列出每根线的道理。
- **自动排版**：
  - 关卡只写零件的「第几列、第几行」；
  - 横屏从左到右排；
  - 竖屏（宽度小于 600）如果列数多于 2、行数不超过 4，整张图转 90°，变成从上到下排，接口改到上下两边，接口文字收起（点接口能看）；
  - 放不下时，接线板在框里横向滑动。
- **验收**：竖屏 390×844、横屏 844×390、桌面 1280×800 三种尺寸下，自动测试按顺序零失误通关全部 37 关。

### 27.14 多条赛道与「同原理」（v2.4 增补，按主创要求「再加直升、双旋、四旋无人机，相同原理放一起，再加一些扩展内容」）

27.12 写的是只有一条赛道时的版式，继续有效。一个学习模块有多条赛道时，在它的基础上这样排：

- **左侧导航**：总览 + 同原理 + 每条赛道一项。每项两行：上面是图标和短名，下面是「通关数 / 总数」；还没解锁的赛道显示锁。
- **总览**：
  - 最上面是「继续：下一关」；
  - 每条赛道一张卡：进度画、名称、一句话介绍、进度条；没解锁的写清楚先通关哪一关；
  - 「同原理」简介和入口；
  - 点 / 线 / 面 / 体图例；课程说明收进「ⓘ 这门课」。
- **赛道页**：
  - 顶部「赛道名 · 通关 n / 总数 · ⓘ 这条赛道」；
  - 进度画（每条赛道一台自己的机器，虚线 = 还在图纸上，实线 = 已经造出来）+ 各阶段的进度小卡，点小卡滚到那个阶段；
  - 阶段不再各占一页，改成一个阶段一段：阶段号、名称、通关数、一句说明，下面是关卡卡片；
  - 有硬件 / 软件全景表的赛道，把表放在页面最后。
  - 从关卡返回时，回到这条赛道并滚到那一关所在的阶段。
- **同原理页**：每个原理一块，写原理名、一句话解释，下面是用到这个原理的所有关卡。
  - 关卡小块的边框颜色 = 所在赛道的颜色，前面带赛道图标；通关后填满颜色；没解锁的变淡；
  - 点小块直接进入那一关；没解锁时提示先通关哪一关；
  - 每个原理至少跨两条赛道，否则不算「同原理」（`tools/check-embodied.mjs` 检查）。
- **关卡里的同原理**：
  - 关卡卡片的小字里写它属于哪个原理；
  - 第一张知识卡下面写一行「同原理：某某——也在某某关」（只是文字，不能点，免得误触离开这一关）；
  - 结算卡里列出同原理的其他关，可以点过去。
- **相同原理放一起排课**：一条赛道里如果有几种相近的机器（比如单旋翼直升机、双旋翼、四旋翼），按「都一样的 → 不一样的 → 又都一样的」分阶段，阶段名直接写「同原理」或「不同之处」。
- **赛道颜色**：每条赛道一个固定颜色，只用在赛道卡的边框和进度条、同原理的小块上；不改页眉、不改主题色。

### 27.15 调参关的多轮与画板、接线板的互换接口（v2.4 增补）

- **多轮**：一关可以分几轮，每轮一个目标。控件上方固定一条「第 n / 总数 轮 + 这一轮要做什么」；过了一轮，提示条写「下一轮：……」，控件保持上一轮的位置，不清零。
- **画板**：调参关可以带一块自己的小画板（曲线、俯视图、步态图……），和指标一起实时更新。
  - 画板第一行用小字写图例；
  - 达标线用绿色虚线，限制线用金色或红色虚线，「你的结果」用最亮的实线；
  - 画板只是帮助理解，过关与否只看指标。
- **每轮都要有解，一开始不能已经过关**：上一轮的答案也不能直接通过下一轮（`tools/check-embodied.mjs` 检查）。
- **互换接口**：一个零件上几个类型相同、作用也相同的接口（比如四合一电调的四路电机输出、配电板的几路输出），接到哪一个都算对；提示会指向还空着的那一个。
- **竖屏转向后的间距**：27.13 里整张图转 90° 时，原来写在上下两边的接口会转到左右两边。这时相邻两列零件之间要留宽一点，接口不能重叠；接口文字一律收起。放不下就在框里横向滑动。
- **验收**：27.13 的三种尺寸下，自动测试按赛道顺序零失误通关全部 76 关；竖屏下任何两个接口的中心距离不小于 16 像素。

### 28.2 水彩的做法（落成代码：`js/watercolor.js`，CF.WC）

1. **纸**：宣纸底色 `#f6efe0`，带细小纤维和颗粒（WC.paper）；CSS 里用 `.wc-paper`（噪点纹理 + 暖色径向渐变）。
2. **颜料是透明的**：一块颜色 = 一个多边形反复「随机外推」变形，再用很低的不透明度叠 20 层左右（WC.wash / blob / band）；中间叠得多更深、边缘浅；边缘再轻描一圈更深的颜色（颜料干了往边上聚）。
3. **墨线勾边**：起笔收笔细、中间粗，带轻微抖动（WC.ink / inkLine / inkCircle / inkRect / arrow）。
4. **字**：标题用楷体（「KaiTi」「STKaiti」等，没有就退回衬线体），正文用系统字体；画布上的字略带歪斜（WC.text）。
5. **颜色只用水彩色卡**（WC.C）：群青、靛蓝、花青、石绿、草绿、藤黄、赭石、胭脂、玫瑰、紫、月白、墨……共 22 色。按钮：纸色底 + 墨色描边 + 小投影；主按钮群青。
6. **夜空**（勇气手账、AI 学徒地图）：深靛底 + 「滤色」晕染 + 星尘；星星在夜空上用「滤色」发光，在纸上用「正片叠底」。月相按真实进度画（0 = 新月，1 = 满月），没有进度时也画一弯新月。
7. **性能**：静态背景只画一次；会动的东西少量重画。一块晕染大约 1 毫秒，一张完整插画 50 毫秒以内。
8. **AI 做的新功能用同一套**：扩展工坊的「水彩小游戏」沙盒里注入同一份源码（ZYWC），模组说明书里写明了用法和色卡（`CF.Mods.spec()`）。

### 28.3 全局 AI 助手

- **入口**：右侧悬浮按钮「✦ AI」，可拖动，位置记在存档；战斗和快速模式中隐藏；有弹窗时缩成贴在右边的小标签，不挡内容，点一下照样打开。
  - 默认位置：玩家没拖过时，从几个候选点（右侧中段、底栏右边的空当、右下角、右侧偏上、左侧中段……）里挑**第一个不压按钮、不压学习计时器**的；每换一个界面、每转一次屏重新挑。玩家拖过以后就一直用玩家放的位置。
- **面板**：独立的一层（在普通弹窗之上），打开它不会关掉正在玩的关卡或弹窗。页眉和普通弹窗一样（标题 + 当前接口 + ✕），下面是标准左侧导航：对话 / 扩展工坊 / 接口设置 / 说明。
- **对话区**：
  - 用户的话在右边（群青色气泡），助手的回答在左边（纸色卡片），上面写模式和模型名；
  - 思考摘要收在「思考摘要」里，默认折起；联网搜索的关键词和来源分别列出；
  - 代码块是深色底，右上角「复制」，网页代码多一个「▶ 运行」：在隔离沙盒里打开（读不到存档和 Key）；
  - 模组代码块显示成一张卡片：名字、类型、会加什么；校验没通过就列出错误，并给「让助手修正」；
  - 每条回答下面：复制、朗读、重新回答、用量（输入 / 输出 / 缓存命中的 token 数）；
  - 出错时用人话说明原因和下一步（Key 不对、模型名不对、余额不足、太频繁、连不上……），不显示英文报错堆栈。
- **输入区**：📎 附件（图片自动缩到长边 1568、文本文件、PDF）、多行输入框（电脑上 Enter 发送）、发送 / 停止；下面是「让助手了解我的进度」「联网搜索」「深度」。
- **空对话**：一幅水彩小画 + 这个模式的三个示范问题，点一下填进输入框。
- **隐私说明必须写在接口设置页**：Key 存在哪里、对话存在哪里、什么会发给平台、谁收费。

### 28.4 扩展工坊（AI 做新内容和新功能）

- 六种模组按安全程度排：知识包、课程包、鼓励包、水彩小游戏、脚本模组、改动提案；每种一张卡片（图标 + 名字 + 一句话），点了先说明、再「发给助手」，也能看模板手写。
- 已装的模组一行一个：开关、使用、导出、卸载。
- 安装前一律校验；脚本模组额外显示代码和风险说明，必须勾选「我看过代码」才能装；工坊顶部显示是否在安全模式。
- 课程包装好以后，在具身智能实验室里就是一条普通赛道，版式按 27.14。

### 28.5 勇气手账与 AI 学徒的版式

- 都是全屏弹窗：页眉不变，左侧导航（手账：今天 / 我的星空 / 他们也失败过 / 给未来的信 / 一分钟呼吸），内容区是水彩纸。
- 手账的「今天」从上到下：夜空横幅（月相）→「我为什么出发」→ 心情（六个水彩色块按钮）→ 回应卡（一句话 + 最小行动按钮 + 可选的 AI 教练）→ 小胜利 → 这一周（七个点，出现就点亮，不要求连续）→ 求助热线。
- 卡住时的鼓励写在关卡自己的提示条里（具身智能第 3 次失误时附一句），不另外弹窗（第 26 章「不遮挡」）。
- AI 学徒：总览是一条水彩小路（7 个站）+ 关卡卡片；进入一关后，知识卡每张一幅水彩小画；底部提示条和按钮粘在底部（同 27.12）。
- 「我的星空」里每条赛道一个星座，位置按赛道顺序固定：横向等分、上下交错，避开右上角的月亮；星座名写在星座正下方，彼此不重叠。
- 大厅右上的「勇气手账」是第四张小卡：整排加宽，原来三张卡保持原宽（约 121px）；卡上的字控制在一行标题 + 最多两行说明。

### 28.6 审核清单增补

- [ ] 新功能用了水彩画风的话，颜色全部来自 WC.C，页眉和导航仍是像素霓虹。
- [ ] 竖屏 390×844、横屏 844×390、桌面 1280×800 下都能完成主要操作；悬浮按钮不挡关键内容。
- [ ] 任何 AI 生成的内容进游戏之前都经过校验；能执行代码的只有两处：隔离沙盒（小游戏、代码预览）和玩家确认过的脚本模组。
